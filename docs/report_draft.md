## 1. EOL 規則說明與背景

### 1.1 背景

在先進製程中，金屬線的線端（end of line）在微影製作時容易變形，例如變圓或縮短。兩條線端如果靠得太近，容易造成短路或良率下降。因此設計規則會要求線端前方保留比一般間距更大的空間，這就是 **EOL spacing rule**。

這條規則在 TSMC、Intel、Samsung 的先進節點都很重要。繞線器（例如 UCSD 的 TritonRoute [1]）在 DRC 檢查時必須遵守它，遇到違規就要另找繞線路徑。

### 1.2 規則內容

> **圖 1**：作業提供的 EOL 規則示意圖（請從作業文件複製）。object 3 落在平行區域內時，object 1 與 object 2 之間需要滿足 EOL spacing。
>
> **圖 2**：TritonRoute [1] 的 EOL spacing 示意圖 Fig. 2(a)（請從作業文件複製）。粉紅色為 EOL spacing 區域：線端前方 EOLSpacing，左右各比線端寬 EOLWithin。

本作業的判斷方式：只要是線端，就檢查它前方的 EOL spacing 區域。

1. **是線端**：末端的邊長 ≤ 0.6 µm。
2. **前方太近**：EOL spacing 區域內有其他金屬。這個區域在線端前方 EOLSpacing（1.0 µm），左右各比線端寬 EOLWithin（0.4 µm）。

兩者都成立就算一個 EOL violation。作業圖 1 另外有平行區域的條件（object 3 落在線端旁邊 0.4 × 0.7 µm 的範圍內），本作業不採用這個條件，不管線端旁邊有沒有金屬都檢查。

| 作業用語 | 論文 / LEF 用語 | 數值 | 來源 |
|---|---|---|---|
| Length of end | eolWidth | ≤ 0.6 µm | 作業給定 |
| EOL spacing | eolSpace | 1.0 µm | 作業給定 |
| Parallel length | parWithin | 0.7 µm | 作業給定，**不採用** |
| Parallel halo | parSpace | 0.4 µm | 作業給定，**不採用** |
| Halo | eolWithin | 0.4 µm | **假設**（作業未給數值） |

### 1.3 判定假設

作業文件沒有說明清楚的地方，本作業採用以下假設：

- **eolWithin = 0.4 µm**：作業沒有給 halo（eolWithin）的數值。圖 1 裡 halo 的寬度看起來和 parallel halo 差不多，所以假設是 0.4 µm。
- **不看平行條件**：每個線端都檢查前方，不管旁邊有沒有金屬（object 3）。
- **Violation region 的邊界不算違規**：間距剛好 1.0 µm，或橫向剛好在 0.4 µm 外，都合法。這和作業寫的 "at least 1" 一致。
- **矩形合併**：同一層重疊或相接的矩形視為同一塊金屬。
- **從 EOL 邊看過去計數**：每條 EOL 邊前方的每一塊太近的金屬各算一個 violation。兩個線端互相面對算兩個；互相重疊或相接的矩形是同一塊金屬，只算一個。
- **分層**：只有同一層的金屬會互相影響。

### 2.2 步驟說明

1. **讀取 layout**：解析輸入檔，把座標從 µm 轉成整數（nm），再依金屬層分組。用整數計算可以避免浮點誤差，例如 2.3 − 1.3 用浮點數會算出 0.9999999999999998。
2. **找出 EOL 邊**：從每個矩形的端點出發，先把相接的矩形接成同一條邊。這條邊的長度 ≤ 0.6 µm，而且兩端都是凸角（線真的在這裡結束），就是一條 EOL 邊。
3. **檢查 EOL spacing 區域**：每條 EOL 邊都檢查前方的 EOL spacing 區域（EOLSpacing 1.0 µm、左右各寬 EOLWithin 0.4 µm）裡有沒有金屬。
4. **判斷違規**：EOL spacing 區域裡有金屬就算違規。
   - 從 EOL 邊看過去：前方每一塊太近的金屬各算一個 violation，位置是 EOL 邊到這塊金屬之間的區域。
   - 互相重疊或相接的矩形是同一塊金屬，只算一個。程式先用 union-find 把它們標成同一塊。
   - 兩個線端互相面對時，兩端各自違規，算兩個 violation。
5. **輸出結果**：把所有 violation 依座標排序後寫入結果檔。

**圖 4**：檢查區域示意（測資 tc07）。

### 2.3 實作重點

- **四個方向共用同一段程式**：程式只處理朝上的 EOL 邊。其他三個方向就把整層旋轉 90°、180°、270°，套用同一段程式後再把結果轉回原座標。
- **空間索引**：把平面切成均勻的格子，每個矩形登記在它蓋到的格子裡。查詢一個區域時只看附近格子裡的矩形，不用把所有矩形兩兩比較（O(n²)）。
- **效能**（隨機產生的 layout，Apple M 系列筆電）：

| 矩形數 | 執行時間 |
|---:|---:|
| 10,000 | 0.02 秒 |
| 100,000 | 0.13 秒 |
| 1,000,000 | 2.0 秒 |

## 3. 結果

### 3.1 作業範例

輸入是作業提供的 6 個矩形，程式輸出如下：

```
number_of_violations 3
1  6.100 1.000,  7.000 1.600
1  6.100 1.000,  7.000 1.600
1  10.000 1.800,  11.400 2.200
end_of_violation
```

每一行代表一個 violation，格式是 `層  左下角 x y,  右上角 x y`，單位 µm。

![圖 5：作業範例的檢查結果](tc00_sample_output.png)

**圖 5**：作業範例的檢查結果

| | 位置 (µm) | 原因 |
|---|---|---|
| V1 | (6.1, 1.0) – (7.0, 1.6) | 從 #4 左端看過去：和 #2 相距 0.9 µm，小於 1.0。 |
| V2 | (6.1, 1.0) – (7.0, 1.6) | 從 #2 右端看過去：和 #4 相距 0.9 µm。和 V1 是同一個縫，但兩個線端各自違規，所以算兩個。 |
| V3 | (10.0, 1.8) – (11.4, 2.2) | #5 上端（寬 0.6）和 #6 相距 0.4 µm，小於 1.0。 |

其他線端都沒有違規，因為前方區域裡沒有金屬。例如 #2 和 #1、#3 都剛好相距 0.4 µm，只碰到 EOL spacing 區域的邊界，不算違規。
